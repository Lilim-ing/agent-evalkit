# Judge 校准

## 为什么必须校准

LLM-as-judge 的问题是：它总会给出一个分数，看起来很像那么回事。但如果它和人工判断的一致性只有 0.3（接近随机），用它做 CI 门禁就是在随机地拦人。

校准要回答一个问题：**这个 judge 的判断，和我会做的判断，一致到什么程度？**

## 流程

1. 从评测集里抽 30-50 条，覆盖"明显好 / 边缘 / 明显差"
2. 人工标注 `human: 0/1`
3. 用 judge 对同样的样本打分，阈值化后记 `judge: 0/1`
4. 写入 `judge_labels.jsonl`

```jsonl
{"human": 1, "judge": 1}
{"human": 1, "judge": 1}
{"human": 0, "judge": 1}
```

5. 计算 κ：

```bash
evalkit calibrate evals/judge_labels.jsonl
```

```
样本 30 · 一致率 86.7% · Cohen's κ = 0.7333 (fair)
judge 一致性可用，但建议只对高分差做门禁
```

## κ 怎么读

| κ | 判定 | 建议 |
|---|---|---|
| ≥ 0.8 | good | 可用于 CI 门禁 |
| 0.6 – 0.8 | fair | 只对明显好/明显差做门禁，边缘样本人工复核 |
| < 0.6 | poor | 不可用于门禁；先改 rubric 或补标注 |

> 为什么不用"一致率"？因为两个都判"通过"的情况占多数时，一致率会虚高。κ 扣除了随机一致的部分。

## 提高一致性的办法

1. **rubric 写具体**：不要"回答质量"，要"是否包含人群、渠道、预算、成功指标四要素"
2. **给锚点**：1 分 / 3 分 / 5 分各给一个示例答案
3. **缩小判断范围**：一次只判一个维度
4. **允许弃权**：judge 可以说"无法判断"，比硬给分诚实

## 样本量

30 条只能粗略判断。要区分 κ=0.6 和 κ=0.7，至少 100 条。样本少时，κ 的置信区间会很宽——报告里应同时给出样本量。

## 本项目的默认 judge

`assertions.default_judge` 是**启发式**（长度、是否含数字、是否含动作词），不是模型。它的存在只是让校准流程离线可跑。接真实模型：

```python
from evalkit.runner import Runner

def my_judge(output: str, rubric: str) -> int:
    # 调你的模型，返回 1-5
    ...

Runner(adapter, judge=my_judge)
```
